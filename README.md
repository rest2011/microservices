# Микросервисная система управления пользователями (Spring Boot + Spring Cloud + Kafka)

Учебный проект, демонстрирующий построение распределённой микросервисной архитектуры с асинхронным взаимодействием через брокер сообщений и использованием ключевых паттернов **Spring Cloud**.

## 🏗 Архитектура и модули системы

Система состоит из 5 независимых микросервисов и инфраструктурных контейнеров:

| Сервис | Порт | Назначение и паттерны |
| :--- | :---: | :--- |
| **`config-server`** | `8888` | **External Configuration** (Spring Cloud Config). Централизованное хранилище настроек для всех микросервисов (профиль `native`). |
| **`discovery-service`** | `8761` | **Service Discovery** (Netflix Eureka). Реестр микросервисов для динамического поиска и балансировки нагрузки без привязки к IP/портам. |
| **`api-gateway`** | `8080` | **API Gateway + Circuit Breaker** (Spring Cloud Gateway + Resilience4j). Единая точка входа в систему с маршрутизацией и защитой от каскадных сбоев (Fallback). |
| **`user-service`** | `8082` | Бизнес-сервис управления пользователями (CRUD, PostgreSQL, Spring Data JPA). Публикует события (`CREATE`, `DELETE`) в Apache Kafka. |
| **`notification-service`** | `8081` | Сервис уведомлений. Читает события из Kafka и отправляет email-сообщения. Реализована обработка сбойных сообщений через **Dead Letter Topic (`user-events-dlt`)**, а также отдельный REST API для прямой отправки писем. |

## 🚀 Инструкция по запуску

### 1. Предварительные требования
* **Java 17**
* **Maven 3.8+**
* **Docker & Docker Compose** (для запуска Kafka и почтового сервера Mailpit)
* **PostgreSQL** (локально запущенная БД `user_db` на порту `5432`)

### 2. Запуск инфраструктуры
Из корневой директории репозитория запустите контейнеры с Apache Kafka и локальным SMTP-сервером **Mailpit**:
```bash
docker compose up -d
```
* Веб-интерфейс для просмотра отправленных писем (Mailpit): `http://localhost:8025`

### 3. Порядок запуска микросервисов
Чтобы сервисы корректно получили конфигурации и зарегистрировались в реестре, запускайте их в следующей последовательности:

1. **`config-server`** (порт `8888`) — дождаться полного старта.
2. **`discovery-service`** (порт `8761`) — панель управления Eureka доступна по адресу `http://localhost:8761`.
3. **`user-service`** (порт `8082`) — перед запуском необходимо задать переменную окружения `DB_PASSWORD` с паролем от PostgreSQL.
4. **`notification-service`** (порт `8081`).
5. **`api-gateway`** (порт `8080`).

## 🔌 Примеры API-запросов (через API Gateway)

Все клиентские запросы направляются на единый порт шлюза **`8080`**:

* **Создать пользователя:**
  ```bash
  curl -X POST http://localhost:8080/api/users \
    -H "Content-Type: application/json;charset=utf-8" \
    -d '{"name":"Иван","email":"ivan@example.com","age":25}'
  ```
* **Получить список пользователей:**
  ```bash
  curl -X GET http://localhost:8080/api/users
  ```
* **Удалить пользователя по ID:**
  ```bash
  curl -X DELETE http://localhost:8080/api/users/1
  ```
* **Прямая отправка уведомления на почту:**
  ```bash
  curl -X POST http://localhost:8080/api/notifications/send \
    -H "Content-Type: application/json;charset=utf-8" \
    -d '{"email":"ivan@example.com","subject":"Приветствие","text":"Тестовое сообщение"}'
  ```

## 🧪 Тестирование
Интеграционные и юнит-тесты в сервисах полностью автономны (используют `@EmbeddedKafka`, `GreenMail`, `Testcontainers` и `MockMvc`) и не требуют запущенного внешнего окружения при выполнении `mvn test`.
